# Native replay UI

Historical review from before the final replay audit and October 7 history squash. See the [latest audit](fresh-audit.md) and [validation record](fresh-validation.json) for the release prepared for publication.

Paddock now uses recorded replay as its main workspace. App navigation, menus, Settings, and session opens contain no live connection, broadcast delay, streaming status, or Watch path. The interface uses SwiftUI/AppKit controls, system fonts, SF Symbols, and recorded team colors on macOS 26.

## Implemented

- A compact session header replaces the oversized flag tile, duplicated titles, and Replay badge. The sidebar slogan and connection footer are removed.
- The default Replay view places the circuit and timing list together in a flexible horizontal workspace constrained to the actual viewport. The partial included timing sample opens in Timing instead of an empty map. A lean replay clock drives recorded car interpolation at 30 Hz, while timing rows remain on the core's slower publication cadence. Map labels reveal selected, hovered, and compared drivers by default. An optional all-label mode uses deterministic collision-aware placement and omits labels that cannot fit rather than stacking them. Map click inspects; Shift-click adds a comparison. The native timing list provides keyboard-accessible selection and context actions.
- Driver detail combines synchronized speed, gear, DRS, throttle, brake, pit/retirement/finish state, lap timing, tyres, and conditions. Telemetry renders at 15 Hz and explicitly shows missing data. Brake is presented as recorded On/Off, not an invented pressure percentage. It does not infer metrics across source gaps or simulate car locations.
- Playback offers 0.1–256× presets, restart, ten-second seeks, lap navigation and direct lap entry. The timeline marks recorded events. Event menu entries include elapsed time to distinguish repeated pit stops. A grouped native Events menu allows named session, flag/safety-car, pit/retirement, and race-control seeks.
- The Laps view compares measured telemetry over distance for two recorded laps, with speed/throttle/brake/gear traces, a shared chart distance domain/crosshair, and comparison-minus-reference time delta when shared coverage supports it. The measured whole-lap difference is displayed separately. Distance traces are not stretched to imply unverified track-position alignment. Qualifying includes recorded Q1/Q2/Q3 best laps and phase filtering. All-phase results sort by highest reached phase and best time; automatic comparison excludes pit laps. Analysis snapshots are keyed by session as well as driver/lap, so switching recordings cannot reuse old traces. Selecting a measured result opens its analysis; Replay lap seeks the same driver/lap in the map. Missing qualifying phases, telemetry, and shared coverage remain explicit.
- Pace and Strategy remain secondary tools. Driver comparison is stored centrally, limited to six, and shared with the map. Expensive completed-lap charts retain equality barriers. Race control preserves named categories, seek chronology, and Follow latest.
- Library covers recorded seasons from 2018 onward, with session filters, search, a native session table, per-session Download/Resume/Open/Redownload/Delete, progress, cancellation, and offline readiness. Partial refreshes retain an Open recording action for the previous committed archive. Missing optional channels are named in the readiness tooltip. Leaving an owned download cancels it and refreshes resumable metadata. Library season, category, search, and download filter are restored when returning from playback. Year requests use identity guards so a new selection cannot be dropped while an old cancelled refresh unwinds. The included Monaco timing sample is distinguished from a full download and offers an explicit upgrade.
- Calendar opens recorded sessions and supports 2018 onward. Settings retains appearance, replay defaults, and download management. Stored defaults are validated. No Python runtime, paid endpoint, or new external dependency is required by the UI.

## Preserved lifecycle and keyboard behavior

The deliberate singleton main Window and separate Settings scene remain. App-owned section commands reopen and restore the main window. The native window bridge combines section selection with actual visibility, miniaturization, and occlusion, independently from application activity. It coalesces visibility publication after representable updates, checks the current window identity, cancels on detach, and reports close/minimize before hidden elapsed time can advance playback. Space is scoped to the active replay window, allows timing tables, and preserves native text/control handling. The previously verified timing driver-cell infinite-width leading frame remains in every timing/qualifying driver cell. The wide inspector preference remains independent of its compact popover.

Prior native lifecycle evidence is retained in [native-window-lifecycle.json](native-window-lifecycle.json). That earlier build retained cursor 3981.2840999901296 with play intent for ten seconds while actually minimized and restored without adding roughly 42 hidden seconds. App activity was false in the hidden snapshot, so that native evidence establishes combined visibility/activity gating. Core tests independently cover the gates. These earlier results do not substitute for a fresh native review of the new replay workspace.

## Current verification

The integrated release build passed Swift 6 complete concurrency checking with warnings treated as errors, plist validation, and strict ad hoc signing. All 73 Swift tests passed. Full Australia 2019 race and Monaco 2024 qualifying recordings opened in the native app. Compact and expanded layouts, inspector toggling, measured lap comparisons, slow and fast playback, table Space, event seeking, and minimized playback were checked. Settings, Calendar, and Championship commands remained usable. [Replay overhaul validation](replay-overhaul.md) records actual archive counts, corrected native constraint behavior, resource samples, and the limits of this evidence.
