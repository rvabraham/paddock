# Services and publication safety audit

Historical review from before the final replay audit and October 7 history squash. See the [latest audit](fresh-audit.md) and [validation record](fresh-validation.json) for the release prepared for publication.

Reviewed October 4, 2026. This report separates credential and privacy exposure from permission to publish code, redistribute data, and consume a service. At audit completion the repository was private, and no audit changes had been committed or pushed. These are audit-time snapshots, not claims about the repository's current status.

## Replay-only follow-up

Later on October 4, the maintainer chose to remove direct live coverage and return the repository to private development. SignalR transport, live reduction, buffering, and their tests were removed. Replay acquisition now uses OpenF1 for races and practice from 2023 onward, and completed-session archives for 2018–2022 and later qualifying. Historical archive access remains separate from permission to redistribute its data. The bundled provider resources were preserved.

The replacement stores versioned, checksummed replay pieces in the user's Application Support directory. OpenF1 coordinate and car-data requests use five-minute windows planned from downloaded session metadata. Validated pieces survive cancellation. A cancelled refresh preserves the prior completed recording, which remains usable offline after restart. Storage checks include both generations, with a 4 GiB library limit, 512 MiB per session folder, and 64 session folders. Recorded sample arrays have a 256 MiB estimated payload budget checked before loading; this is not a total process-memory limit.

The integrated replay-only source passed 67 Swift tests under complete Swift 6 concurrency checking with warnings treated as errors. Tests cover compact sample integrity, cancellation and resume, offline restart, prior-generation recovery, storage and typed-payload budgets, metadata extending a session's finish, and preservation of only exact matching acquisition ranges. Release-build and native checks were still in progress when this follow-up was written. The 51-test validation record below belongs to the earlier live-capable version and does not validate this replacement source.

The new service source, tests, README, and notices were scanned for common credential markers and personal home-directory paths without a finding. Direct-live endpoint strings remain only in rejection tests. No provider fixture or icon resource was changed during this overhaul.

## Result

The inspected history contained no observed credential or private personal-data blocker. That supports a limited statement about the scanned repository, not a guarantee about every possible secret format or future change. Original application code has the user-selected MIT license. The repository audited then also contained provider responses and a direct Formula 1 live-feed client. Their rights were separate and remained the consequential publication uncertainty.

Jolpica's [API terms](https://github.com/jolpica/jolpica-f1/blob/main/TERMS.md) explicitly license API data under CC BY-NC-SA 4.0. OpenF1's [site](https://openf1.org/) and [project license](https://github.com/br-g/openf1/blob/main/LICENSE) identify the same license, but its FAQ says credits are not required and it disclaims ownership of underlying Formula 1 data. Conservative attribution is now recorded in `THIRD_PARTY_NOTICES.md`. This does not establish rights from every upstream owner.

Formula 1's [guidelines](https://www.formula1.com/en/information/guidelines.4EOKE9RRqevL4niTK9kWyt) assert timing-data and database rights and restrict app use and substantial reproduction. Its [legal notices](https://www.formula1.com/en/information/legal-notices.7egvZU48hzrypubGBNcQKt) reserve live and historical data rights and restrict redistribution. No published permission for this third-party `/signalrcore` client was found. A successful unauthenticated connection establishes technical access only.

After the original audit, the maintainer initially chose source publication as a noncommercial hobby project and accepted ordinary project risk. That preparation kept the bundled data and experimental live feature, with their separate terms and unresolved upstream rights disclosed. No visibility change was made during the audit or documentation preparation. The subsequent replay-only decision is recorded above. Neither decision asserts upstream permission or clearance.

## Original audit fixes supported by code evidence

| Before | Result |
| --- | --- |
| Default URLSession cache could satisfy a forced refresh independently of the app's disk cache. | HTTP uses an ephemeral session with URLCache disabled, explicit reload policy, and a separate bounded disk cache. Library refresh can bypass both session and meeting response caches. |
| OpenF1 reserved future slots, while Jolpica had no application quota gate. Cancelled callers could leave reserved delays behind. | A shared actor gates actual starts with monotonic uptime. OpenF1 is spaced at 2.1 seconds with a 30-per-minute rolling window; Jolpica at 0.3 seconds with 500 per hour. Waiting callers recheck after waking and do not reserve abandoned future slots. |
| Retry-After assumed a numeric finite value. An infinite value could trap during nanosecond conversion, and a final failed retry did not defer subsequent requests. | Numeric and HTTP-date values are parsed; nonfinite values use a safe fallback. Every 429 installs shared backoff, including the final failed attempt. Cancellation remains effective while waiting. |
| Entire responses were collected before any body-size check. | A shared URLSession data delegate appends Data chunks and cancels when the declared or received response exceeds 16 MiB. Error status bodies are cancelled immediately. HTTPS redirects must retain the original host, avoid URL credentials, and use the default HTTPS port. |
| Clearing the cache while requests were suspended could restore old response or replay files. | Cache generations suppress writes from earlier requests; replay generation checks prevent an earlier download from being published after clear. |
| Response and replay storage grew without a limit. | Response cache: 100 MiB, 300 entries, 16 MiB per entry. Replay cache: 512 MiB, 64 saved sessions plus a small index, 64 MiB per replay. Oldest regular JSON files are removed at initialization and after writes. Oversized old entries are included in cleanup. |
| Cache reads could follow file or cache-directory symlinks, and cachedKeys counted arbitrary numeric filenames. | Cache reads require regular, bounded JSON files and reject symlink roots, direct parents, and entries. Filenames cannot traverse directories. Replay badges come from validated metadata and existing files. |
| Every library scan decoded large replay files; a valid header could advertise an unusable replay. | A replay is validated once per size/modification fingerprint. A bounded metadata index serves later scans. Invalid or mismatched sessions are excluded, and evicted files are rechecked before returning badges. |
| A disk save failure was indistinguishable from a successful saved-session badge. | Valid downloaded data can still open in memory, while the library's cached keys are read from persisted files. |
| Download endpoints waited serially for each network response. | A scoped task group overlaps eight independent downloads. All starts still pass through the same provider rate gate; a failure cancels the group and publication remains atomic. |
| Recent historical responses could be cached for a year immediately after the live window. | Responses for a session ending within the last week use a one-hour lifetime to allow early archive corrections. Older historical responses retain the long cache lifetime. Saved replays remain offline copies. |
| lapTime silently dropped malformed colon components and accepted nonfinite or implausibly large durations. | Every component must parse, subordinate units must be below 60, and durations must be positive, finite, and no longer than 24 hours. Invalid date-only calendar days are rejected, with Gregorian dates preserved in the local time zone. |
| SignalR cancellation could wait on an outstanding receive; overlapping runs could interfere with shared cleanup. | Each run has a generation. Cancellation immediately closes its local transport. Cleanup only touches the matching run, and explicit stop cancels negotiation, socket, and keepalive. |
| The live parser converted fragments to strings independently, accepted a hub frame as a handshake, and accepted any completion as a snapshot. | A bounded byte buffer preserves split UTF-8; handshake framing is checked and only the matching subscription completion installs a snapshot. Unknown and unused topics are ignored. |
| A healthy transport could be called connected before its subscription succeeded, or remain stuck waiting indefinitely. | Connected is emitted after subscription completion. Startup and receive watchdogs close stalled sockets so the store can reconnect. A watchdog close is distinguished from user cancellation. |
| A hidden live view stopped its ticker and could keep reporting live indefinitely when only heartbeats arrived. | Heartbeats drain eligible delayed frames and refresh connection health without rebuilding displayed arrays or starting a hidden-view ticker. Heartbeats never advance the timing-data freshness timestamp. Returning to the view publishes its accumulated state. |
| A time window and per-message size limit did not bound dense retained bursts or growing merged topics. | Retained events have a 64 MiB estimated payload budget and a 50,000-frame ceiling. Merged topics have a separate 32 MiB estimate limit. Overflow cancels the connection and ticker, invalidates callbacks, releases buffered state, and preserves the last published snapshot with an actionable error. |

Responsibilities are now in `ProviderHTTP.swift`, `BoundedHTTPTransport.swift`, `DiskCache.swift`, `RaceProvider.swift`, `ProviderDecoders.swift`, `ProviderError.swift`, and `SignalRService.swift`. Replay and live reduction have their own files and audits. The native build and test scripts include the new sources through their existing globs.

Provider quotas and cache generations are actor isolated. The URLSession transport and its delegate/transfer helpers use `@unchecked Sendable`; immutable references or locks protect their shared state. Continuations are removed under the lock before they resume, so cancellation and completion cannot resume the same transfer twice. The URLSession delegate is a separate object, allowing the transport to invalidate its session when released.

## Original audit verification

Final integrated validation passed Swift 6 complete concurrency checking with warnings treated as errors and 51 tests across eight suites in 4.678 seconds. Fifteen focused service tests cover cache bypass, clearing during an in-flight response, cancellation, bounded responses with and without Content-Length, 8 MiB chunk integrity, URL and redirect policy, quota and backoff behavior including the final failed retry, finite Retry-After parsing, storage eviction, symlink/path handling, fragmented UTF-8, subscription identity/errors, and malformed measurements. Lifecycle tests verify hidden-view freshness, retained displayed rows, publication on returning to the view, and cancellation of an already queued ticker callback. Seven budget tests cover event/frame rejection, compaction, merged-topic growth, overflow disconnection, retained published state, and stale callback rejection.

The final clean release build passed plist validation, ad hoc signing, atomic replacement, and an independent deep/strict signature verification. Bundled LICENSE and THIRD_PARTY_NOTICES.md matched the source files. The 8.9 MiB app launched successfully; the six-driver Pace limit and pane preferences passed native checks. Temporary source diagnostics were removed, and bundled data and icon resources were unchanged.

The [final validation record](validation.json) preserves the source fingerprint, build/test results, and native checks, including main-window reopening while Settings remains open.

The fixture tooling passed 15 mocked tests and offline validation of all 12 bundled JSON responses. No source fixture was downloaded or replaced during the audit.

The 8 MiB mock transport test took 0.179 seconds in an earlier concurrent run and 0.094 seconds in the final 51-test run. These verify chunk handling and give local cost observations. They are not network benchmarks or comparisons with the previous transport. The largest bundled response is `monaco2024/intervals.json`, 3,379,689 bytes and 23,976 rows. The inspected local response cache's largest file was 3,528,412 bytes, and its largest saved replay was 4,141,005 bytes. The 16 MiB response cap exceeds those observed workloads; unusual larger sessions can still be rejected with an explicit error.

Quota settings were checked against [OpenF1 access information](https://openf1.org/) and [Jolpica's current rate guide](https://github.com/jolpica/jolpica-f1/blob/main/docs/rate_limits.md). Jolpica warns that unauthenticated limits may decrease and that a shared IP can exhaust its quota. App quotas are per process, so provider 429 handling is still required. SignalR framing and invocation identity follow Microsoft's [hub protocol specification](https://github.com/dotnet/aspnetcore/blob/main/src/SignalR/docs/specs/HubProtocol.md).

Wind-speed units were checked against [OpenF1 weather documentation](https://openf1.org/docs/#weather) and the [FastF1 maintainer's direct WeatherData parser](https://github.com/theOehrly/Fast-F1/blob/master/fastf1/_api.py). Both identify m/s; the latter consumes live WeatherData without unit conversion. Keeping m/s is supported by that adapter evidence, rather than by an official Formula 1 feed contract.

Native validation connected to the unauthenticated feed and received a completed-session snapshot with 22 drivers at lap 55. The sidebar, session label, and banner described that state accurately. Disconnect retained the snapshot and showed Disconnected. The feed supplied inconsistent session/location metadata, which the app did not silently replace with an invented correction. Sustained changing updates during an active session remain unverified. A completed-session snapshot, synthetic feed tests, or a successful negotiation cannot prove that coverage. Further native results are recorded in the UI audit.

The [native window evidence](native-window-lifecycle.json) confirms that a truly minimized window retained its exact replay cursor and play intent for ten seconds with no intervening computer-use read. Command–1 restored playback with 0.506 seconds of normal advance and no hidden elapsed-time jump. Closing the main window while Settings remained open and reopening Replays with Command–3 also passed. The hidden sample had both visibility and activity gates false, so this validates their combined behavior; core tests exercise those gates separately.

## Remaining limits and publication context

- Original code is MIT licensed. Bundled provider data, third-party research excerpts, trademarks, linked media, and service access are excluded. `LICENSE` and `THIRD_PARTY_NOTICES.md` should travel with any distributed app or source copy.
- The JSON fixtures are substantial race data, not a small incidental editorial quotation. They were already present in the initial commit. Deleting them only from a later working tree would leave that material in public history; a code-only publication would need an explicitly chosen history strategy.
- The original fixture retrieval times were not recorded. `scripts/fetch-fixtures.py` provides the exact query provenance; the Git commit date is not substituted for a download timestamp.
- No Formula 1 endpoint license for this app was found. That is an unresolved permission question, not a finding that a credential has been bypassed. The app does not use accounts, keys, paid topics, proxies, or subscription circumvention.
- Cache writes can fail, and disk cleanup cannot overcome changed filesystem permissions. Valid data still opens in memory. Symlink protection checks the cache root, its direct parent, and entries; it is not a defense against a hostile process with the same user's filesystem privileges or atomic path replacement races.
- Metadata fingerprints avoid repeated multi-megabyte decode work. They are not cryptographic integrity checks against same-user modification. A replay is parsed and validated again when opened.
- Live budgets estimate retained event payloads and merged topics. They are not process-RSS limits and do not include temporary decode/merge allocations or derived lap history, which is retained per session. No whole-app memory or energy improvement is claimed.
- Saved replay data is an offline copy and is not automatically redownloaded for later provider corrections. Unusually large responses, missing topics, archive gaps, malformed provider data, and undocumented live transport changes can limit coverage.
- The tested app uses a local ad hoc signature. It is not Developer ID signed or notarized for distribution to other Macs.
